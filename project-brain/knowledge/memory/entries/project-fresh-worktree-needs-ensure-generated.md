A fresh Augur worktree (newly created, never built) will FAIL a handful of tests across all three runners even though the code is correct, because those tests assert against **gitignored generated output** that only exists after a dashboard build. The fix is to run `pnpm run ensure-generated` once inside `apps/dashboard` (this runs `build:scripts` to compile `scripts/dist/*.mjs`, then `rebuild-plugins`/mount-plugins to generate `apps/dashboard/app/{hub}/` routes and the `plugins/augur` bundle). It does NOT need the dev server, so it is far lighter than `/dev-build`.

Tests that depend on this generated state:
- `tests/integration/test_skill_parity.py::TestDashboardPageParity::test_hub_pages_exist` — needs `apps/dashboard/app/brain/.../page.tsx` (gitignored, generated by mount-plugins).
- `tests/dashboard/scripts/validate-nav-alignment.test.ts` — runs the compiled `apps/dashboard/scripts/dist/validate-nav-alignment.mjs` (needs `build:scripts`) and counts `plugins/` bundle dirs (needs the generated `plugins/augur`).

**Why:** `apps/dashboard/.gitignore` ignores `/app/{adaptive,brain,command,dev,life}/` and the `plugins/augur` skill mount; CI builds before/around these but a clean local worktree doesn't.

**How to apply:** When starting test work in a fresh worktree, run `pnpm run ensure-generated` in `apps/dashboard` first, then run the three suites. NOTE: `plugins/orchestration/` is NOT a generated bundle — that subsystem was removed; any such dir is stale runtime scaffolding, so `EXPECTED_BUNDLE_COUNT` in validate-nav-alignment is 5 (agents, augur, lib, obsidian, vscode).
