# /dev-clean

Idempotent repo hygiene. Removes regenerable artifacts that `.gitignore` already excludes and reports bytes/files reclaimed. Safe defaults: Tier 1 only — no `.git` or global package-store mutation unless `--include-git` or `--all` is passed.

Wraps `project-brain/capabilities/skills/platform-admin/scripts/dev_clean.py`.

## Gotchas

### 1. Tier 1 is always safe; Tier 2 touches `.git` and the pnpm store
Tier 1 only deletes targets that are already gitignored and that some other tool will regenerate (pnpm, uv, pytest, Python interpreter). Tier 2 runs `git lfs prune --verify-remote`, `git gc --prune=now`, and `pnpm store prune`. Git operations verify reachability against the remote and reflog before deleting. `pnpm store prune` removes unreferenced versions from the global pnpm store; future installs may re-download packages. Tier 2 requires the explicit `--include-git` or `--all` flag.

### 2. The dashboard dev server should be stopped first
`apps/dashboard/node_modules/.ignored` is not touched at runtime, but pnpm/Next may hold open file handles on Windows. If the dev server is running, stop it (`/dev-build --stop` or close it) before running `--include-git` to avoid Windows file-lock errors.

### 3. After `/dev-clean`, the next `pnpm install` / `uv sync` may take longer
That is expected — caches were emptied. The actual installed `node_modules` and `.venv` are not touched. `/dev-clean --all` also prunes the global pnpm content-addressable store, so the next `pnpm install` may re-download packages from the registry.

## Usage

```bash
/dev-clean                       # Tier 1 only, executes
/dev-clean --dry-run             # Report what Tier 1 would reclaim, delete nothing
/dev-clean --include-git         # Tier 1 + Tier 2 (LFS prune + git gc + pnpm store prune)
/dev-clean --all                 # Alias for --include-git
/dev-clean --dry-run --all       # Report Tier 1 + Tier 2 without touching anything
/dev-clean --json                # Machine-readable output
```

## Execution Steps

See [../references/dev-clean-execution-steps.md](../references/dev-clean-execution-steps.md) for the full list of operations, what each one removes, and why removing it is safe.

## What Gets Reclaimed

| Tier | Operation | Target | Why safe to remove |
|---|---|---|---|
| 1 | `pnpm-ignored-cache` | `apps/dashboard/node_modules/.ignored` | pnpm's stale-symlink graveyard; never read at runtime |
| 1 | `duplicate-mcp-venv` | `src/mcp/.venv` | Shadowed by root `.venv`; the root `uv sync` covers all needs |
| 1 | `pycache-purge` | All `__pycache__/` under `project-brain/`, `src/`, `scripts/` | Python bytecode; regenerated on next interpreter run |
| 1 | `tool-caches` | `.pytest_cache`, `.ruff_cache` | Tool caches; regenerated on next pytest/ruff run |
| 1 | `stale-dashboard-worktree-caches` | inactive `get_cache_dir()/dashboard-worktree-*` directories | External Next/Turbopack worktree caches; regenerated by `/dev-build`, and live Next lock PIDs are skipped |
| 2 | `git-lfs-prune` | Orphaned `.git/lfs/objects` already on remote | `--verify-remote` enforces no unpushed loss |
| 2 | `git-gc` | Unreachable git objects + pack consolidation | Only touches what is unreachable from any ref/reflog |
| 2 | `pnpm-store-prune` | Unreferenced versions in `~/Library/pnpm/store/` (or platform equivalent) | `pnpm store prune` only removes versions no current `node_modules` references; next install re-downloads |

## Options

| Flag | Description |
|------|-------------|
| `--dry-run` | Report what would be reclaimed without deleting anything |
| `--include-git` | Also run Tier 2 (`git lfs prune --verify-remote`, `git gc --prune=now`, `pnpm store prune`) |
| `--all` | Alias for `--include-git` |
| `--json` | Emit machine-readable JSON instead of the table |

## Examples

- `/dev-clean --dry-run` — Audit reclaimable space without touching the filesystem
- `/dev-clean` — Reclaim Tier 1 (typical recurring hygiene; often GBs when old dashboard worktree caches exist)
- `/dev-clean --all` — Full cleanup including `.git` compaction and pnpm store pruning; run occasionally after big merges or dependency churn
- `/dev-clean --dry-run --json` — Pipe into a report or auto-loop without parsing the table

## Idempotence

Re-running on a clean tree is a no-op — every operation reports zero bytes reclaimed and zero targets touched. The script never deletes anything outside its declared target list and refuses to operate outside the repo root.

## When Not to Use

- **During a failing `pnpm install`**: do not run `--include-git` while pnpm holds file locks on `node_modules`. Let install finish (or kill it) first.
- **Pre-merge with uncommitted LFS work**: `--include-git` verifies LFS against remote, but a stash containing LFS pointers that have not been pushed will be lost from the local LFS cache. Push first if in doubt.
- **As a workaround for `/dev-build` failures**: if the dashboard build is failing, run `/dev-debug` first. Cleaning caches can mask a real bug.
