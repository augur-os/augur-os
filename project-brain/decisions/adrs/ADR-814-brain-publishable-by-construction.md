# ADR-814: Brain Publishable by Construction — Owner-Private Memory Layer

## Context

ADR-811 established the project brain as the home for decisions, knowledge, and memory. The brain ships as part of the product release (via `src/lib/release_workspace.py`), which means any tracked file under `project-brain/` that reaches a release tree is visible to new users of the product.

Prior to this ADR, publishability was treated as a release-time concern — a scramble to scrub private content before each cut. This approach creates risk: contamination is discovered late, human judgment decides what is safe at the worst moment, and the publish test has no continuous enforcement.

Inspection of the tracked brain tree before this ADR found:
- 115+ ADR bodies containing absolute machine paths (`~/...`)
- A `BRAIN.yaml` manifest with absolute `root:` and `attached_project:` paths
- An inventory JSON file with per-artifact `source_path` and `project_root` fields containing machine paths
- Skill test fixtures and scripts hardcoding real machine paths
- RAG seed pages with `source_path:` frontmatter fields containing machine paths
- Client memory sweep entries writing `source_path: <absolute>` provenance

The `knowledge/memory/` subtree is categorically owner-private: it contains the current owner's swept client memory, personal insights, and live context. Shipping it would expose the owner's private operational state to new users.

## Decision

**1. The project brain ships with the product release.** ADR-811's visibility model is enforced continuously from day 0, not at release time. Every commit that touches `project-brain/` must be publishable.

**2. Memory is the owner-private layer.** `knowledge/memory/` and the generated `MEMORY.md` at the brain root never ship with the product. The product release prune step removes them entirely. A shipped brain starts with empty memory and fills with the new owner's operational context through normal use.

**3. Brain publish lint.** A repo test (`tests/unit/test_brain_publish_lint.py`) continuously scans all tracked files under `project-brain/` for machine paths and secret markers. New content failing the publish test fails CI at commit time.

Exemptions from the lint:
- `project-brain/knowledge/memory/**` — owner-private; removed at release
- `project-brain/MEMORY.md` — generated index of the owner-private memory entries
- `project-brain/**/.obsidian/**` — Obsidian workspace metadata, not brain content

Banned binary suffixes (any tracked file under `project-brain/` with these suffixes is a lint failure regardless of content):  `.zip`, `.pptx`, `.mp4`, and the full set defined in `scripts/guard_public_release_tree.py:FORBIDDEN_FILE_SUFFIXES`.

Content markers that fail the lint (any text file under `project-brain/` outside exemptions):
- `/Users/` — any macOS/Linux machine user directory
- `C:\Users\` — any Windows machine user directory
- `PRIVATE KEY` — private key material
- `OPENAI_API_KEY` — credential literal
- `ANTHROPIC_API_KEY` — credential literal
- `github_pat_` — GitHub PAT prefix
- `ghp_` — GitHub PAT short prefix

The `/Users/` marker is intentionally broader than the prior guard (`~`): any machine path is disqualifying, not only the current owner's.

**4. No absolute paths in brain config.** `BRAIN.yaml` uses relative paths (`root: .`, `attached_project: ..`). Brain tooling resolves them against the manifest's directory. Downstream consumers that receive a `BrainManifest` already resolve `attached_project` relative to the brain root when the value is not absolute (see `src/lib/brain_context.py:resolve_active_context`).

**5. Sweep provenance stores filenames, not absolute paths.** `src/lib/client_memory_sweep.py` writes `source_file: <basename>` instead of `source_path: <absolute path>` in swept-entry frontmatter. `source_client` and the project context identify the origin; the absolute machine path is not needed and would contaminate the publishable brain tree.

## Consequences

- The brain tree is publish-safe from every commit. Release preparation requires no manual scrubbing.
- New product users receive a brain with empty memory, correct relative config, and no trace of the previous owner's machine.
- The owner's operational memory persists in the private vault and local `knowledge/memory/` directory; it is never lost — only not shipped.
- Skill tests that previously hardcoded machine paths must use `tmp_path`-derived or neutral placeholder paths. This is a correctness fix: tests that only pass on one machine were not meaningful CI.
- The `ai-artifacts.json` inventory (generated by the artifact scanner) stores `source_path` fields as an operational cache. It is regenerated at runtime and is exempted from the publish test by being categorized as machine-local operational data — it should not be tracked in the brain tree at all (TODO_CLEANUP: remove from git tracking post-ADR-814).
