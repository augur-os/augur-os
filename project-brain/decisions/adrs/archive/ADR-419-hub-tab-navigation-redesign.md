# ADR-419: Hub Tab Navigation Redesign

## Context

Hub pages had no horizontal tab navigation. After hub root pages were removed (ADR-406), the only way to navigate between pages within a hub was via the sidebar, showing one vertical entry per skill. Custom pages, auto pages, and blocks were all hidden or mixed together with no visual distinction. Users couldn't discover or access most pages without knowing the URL.

## Decision

Add a horizontal tab bar (`HubTabBar`) at the top of every hub page that:

- Shows **custom pages** (`page_type: custom`) as primary horizontal tabs with responsive overflow into a "More" dropdown
- Adds a **Blocks** dropdown (right-anchored) listing all `contributions.blocks` for the hub, grouped by skill
- Adds an **Auto** dropdown (right-anchored) listing all `page_type: auto` pages, grouped by skill
- Hides Blocks/Auto buttons when a hub has none of that type

### Registry Changes

The generated tab registry splits from a flat tab list to a three-way split: `tabs` (custom pages visible), `overflow` (custom pages that overflow), `blocks` (from `contributions.blocks`), and `autoPages` (`page_type: auto`).

### Component Architecture

```
app/{hub}/layout.tsx (generated by mount-plugins)
├── HubHeaderSection
├── HubTabBar
│   ├── TabList (horizontal custom page tabs)
│   ├── OverflowDropdown ("More ▾")
│   ├── BlocksDropdown ("Blocks ▾", grouped by skill)
│   └── AutoPagesDropdown ("Auto ▾", grouped by skill)
└── {children}
```

### Scale

Across 15 hubs: 93 custom pages, 55 auto pages, 136 blocks.

## Consequences

### Positive

- Users can discover and navigate to all pages within a hub from a single tab bar
- Responsive overflow prevents UI clipping
- Blocks and auto pages are accessible without knowing URLs

### Negative

- More complex tab registry generation
- ResizeObserver adds client-side computation

### Neutral

- Sidebar navigation unchanged — still shows one entry per skill
- Individual page.tsx files unchanged

## Alternatives Considered

### Alternative 1: Sidebar-Only Navigation

Keep navigation entirely in the sidebar. Rejected because sidebar doesn't distinguish custom/auto/block page types and becomes overwhelming with 200+ pages.
