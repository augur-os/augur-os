# ADR-547: Second Brain Intelligence Report

## Context

After ADR-546 made wiki pages the synthesis layer, the knowledge they contain was invisible outside the local vault — useful to the agent but not shareable. The OSS launch (ADR-537) needs a demo artifact that answers the question "what can Augur actually do?" in a single screenshot. A generic dashboard screenshot doesn't capture the value. Something that says "I dropped 1,035 files; my AI read them all and wrote this about me" does.

The report also needs to demonstrate that Augur's knowledge is personal and high-quality — patterns, blind spots, cross-domain connections — not just a file counter.

## Decision

`/wiki report` generates a "Second Brain Intelligence Report" as a PDF + HTML artifact. The agent reads all wiki pages, synthesizes human-style insights (not metrics), and calls `wiki-report-generate` to render them.

**Command:**
```
/wiki report [--style demo|editorial|minimal] [--hub <hub>] [--output <path>]
```

Default style: `demo` (dark mode, data-rich). Default output: `{vault}/reports/second-brain-report-YYYY-MM-DD.pdf` + `.html`.

### Report Structure (4 pages)

| Page | Content |
|------|---------|
| Cover | One-paragraph AI synthesis of the user ("what your AI knows about you"), stat bar, portfolio photo if available |
| Who You Are | What You Do, How You Think (from ADRs + behavioral data), Expertise Stack (ranked bars with Expert/Advanced/Active/Growing labels) |
| What Your Brain Contains | Per-hub narrative paragraphs — actual knowledge summaries, not page listings |
| Patterns & Blind Spots | Cross-domain connections, behavioral patterns, thin domains, specific gap recommendations |

### Generated Visualizations (embedded PNG)

- **Knowledge Radar** — spider chart, depth per domain, rendered via matplotlib
- **Knowledge Graph** — force-directed node graph of wiki pages linked by `[[wikilinks]]`, colored by hub, sized by cross-reference count, rendered via networkx + matplotlib
- **Hub Distribution Bar** — horizontal stacked bar of source distribution, rendered via matplotlib

Charts output to `{runtime}/wiki/report-assets/`, embedded in both PDF and HTML.

### 2 MCP Tools

| Tool | Type | Purpose |
|------|------|---------|
| `wiki-report-data` | read | Aggregates stats, page metadata, cross-reference counts — saves agent from 50+ individual wiki-read calls |
| `wiki-report-generate` | mutation | Mechanical renderer: takes structured JSON (sections, insights, stats, image paths) → PDF + HTML |

The agent does all thinking (insight writing, pattern extraction, blind spot identification). `wiki-report-generate` is a pure renderer using ReportLab (PDF) and Jinja2 (HTML).

### Portfolio Folder

`{vault}/portfolio/` — optional images placed contextually by filename pattern (`profile.*` → cover, `{hub}-*.*` → hub section, `logo.*` → footer). Missing images skipped gracefully.

### Rendering Stack

| Format | Library |
|--------|---------|
| PDF | ReportLab |
| HTML | Jinja2 (self-contained, inline CSS) |
| Charts | matplotlib + networkx |

### Skill Structure

Added to `skills/ingest/scripts/`: `wiki_report.py` (data aggregation), `wiki_report_render.py` (ReportLab + Jinja2), `wiki_report_charts.py` (chart generators). Template at `skills/ingest/assets/templates/report.html.j2`. Command at `skills/ingest/commands/wiki-report.md`.

## Consequences

### Positive

- Shareable demo artifact that shows Augur's value in one screenshot
- Forces the wiki to be good — if it's empty or sparse, the report shows it
- Augur branding on every share ("Generated by Augur — augur.run") is free marketing
- "Editorial" and "minimal" style variants are straightforward additions using the same data pipeline
- Personal profile photos and hub images make it visually distinct from generic BI reports

### Negative

- Report quality is directly proportional to wiki quality — sparse wiki → thin report
- First generation on a large wiki is slow (agent reads all pages sequentially before calling the renderer)
- ReportLab and networkx add to the dependency surface
- `demo` style (dark mode gradient) may look dated quickly — design-sensitive

### Neutral

- `wiki-report-data` convenience tool reduces LLM context usage at report time but isn't required for correctness
- Phase 1 implements `demo` style only; `editorial` and `minimal` are future template additions
- Charts are pre-rendered PNGs — consistent between PDF and HTML without a separate chart server

## Alternatives Considered

### Alternative 1: Dashboard page (interactive, browser-only)

Render the report as a live dashboard page. Rejected: not shareable as a file, requires dashboard to be running, and doesn't produce the screenshot-and-share artifact that the OSS launch needs. A static PDF achieves the viral goal.

### Alternative 2: Markdown report only (no PDF/charts)

Generate a well-structured markdown file. Rejected: plain markdown doesn't showcase Augur's capability visually, can't be tweeted as a single image, and loses the "analyst briefing" aesthetic that makes it feel premium.

### Alternative 3: Third-party report service (e.g., Retool, Redash)

Export data to an external tool for rendering. Rejected: breaks the local-first principle (data leaves the machine), adds an external dependency, and requires users to have accounts.
