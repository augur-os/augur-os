# Turbopack Performance: Hub Catch-All Routes + Page Splits

**Date:** 2026-03-22
**Status:** Draft
**Problem:** Dashboard dev server consumes 3-5 GB RSS and 484% CPU because Turbopack maintains module graphs for all 140 page routes. The 8 GB heap ceiling (`--max-old-space-size=8192`) lets V8 grow unchecked, and the top 5 pages are 918-1529 lines each.

## Decision

Replace 140 individually mounted page.tsx files with 6 hub-level optional catch-all routes (`[[...slug]]/page.tsx`) backed by auto-generated registries. Split the top 5 oversized pages into focused sub-pages. This reduces Turbopack route entries from ~140 to ~25 (6 catch-alls + ~19 native routes) and per-visit compile cost by ~70%.

## Context

- 140 page routes, 89% auto-generated from plugins via `mount-plugins.mjs`
- `mount-plugins` copies full source files into `apps/dashboard/app/{hub}/{path}/page.tsx`
- `turbopack.root` is set to monorepo workspace root, so Turbopack watches the entire tree
- `start-dev.sh` sets `--max-old-space-size=8192` (8 GB heap), causing V8 GC to defer until 5+ GB RSS
- Top 5 pages: `ai_bridge` (1529), `daemon` (1092), `reading-list` (1019), `workbench` (950), `learning` (918)
- `AUGUR_DEV_HUBS` env var exists but is not a solution — user works across all hubs
- 46 `loading.tsx` files and 25 `layout.tsx` files exist in hub subdirectories (all passthrough)
- `generate-tab-registry.ts` validates that mounted `page.tsx` files exist on disk (ADR-177, lines 640-684)
- Hub landing pages (`brain/page.tsx`, etc.) use server-side `redirect()` to default tab

## Design

### Phase 1: Hub Catch-All Routes

#### File Structure

```
apps/dashboard/app/
  brain/[[...slug]]/
    page.tsx          # optional catch-all (~40 lines)
    registry.ts       # auto-generated: slug -> import path
  career/[[...slug]]/
    page.tsx
    registry.ts
  command/[[...slug]]/
    page.tsx
    registry.ts
  life/[[...slug]]/
    page.tsx
    registry.ts
  studio/[[...slug]]/
    page.tsx
    registry.ts
  adaptive/[[...slug]]/
    page.tsx
    registry.ts
  settings/           # native pages — unchanged
  (views)/             # native pages — unchanged
  api/                 # API routes — unchanged
```

Uses `[[...slug]]` (optional catch-all) instead of `[...slug]` so the bare hub path (`/brain`) is handled by the same component — no separate hub-level `page.tsx` needed.

#### Catch-All Page (~40 lines)

Each hub gets an identical catch-all that reads the slug, looks up the component in the registry, and renders it via `next/dynamic`. Empty slug redirects to the hub's default tab. Components are cached at module level to prevent remounts on re-render.

```tsx
'use client';
import dynamic from 'next/dynamic';
import { useParams, useRouter } from 'next/navigation';
import { useEffect } from 'react';
import { PAGES, DEFAULT_PATH } from './registry';

const DynamicCache = new Map<string, React.ComponentType>();

function getDynamicPage(path: string) {
  if (!DynamicCache.has(path)) {
    const loader = PAGES[path];
    if (!loader) return null;
    DynamicCache.set(path, dynamic(loader, {
      loading: () => <div className="animate-pulse h-full min-h-[200px]" />,
    }));
  }
  return DynamicCache.get(path)!;
}

export default function HubPage() {
  const { slug } = useParams<{ slug?: string[] }>();
  const router = useRouter();
  const path = slug?.join('/') ?? '';

  useEffect(() => {
    if (!path && DEFAULT_PATH) {
      router.replace(DEFAULT_PATH);
    }
  }, [path, router]);

  if (!path) return null;

  const Page = getDynamicPage(path);
  if (!Page) {
    return (
      <div className="flex items-center justify-center h-64 text-[var(--text-muted)]">
        Page not found: {path}
      </div>
    );
  }

  return <Page />;
}
```

#### Registry File (Auto-Generated)

Mount-plugins generates one `registry.ts` per hub mapping slug paths to lazy import functions. Includes the default redirect path for each hub.

```tsx
// AUTO-GENERATED by mount-plugins — do not edit
export const DEFAULT_PATH = '/brain/knowledge/memory';

export const PAGES: Record<string, () => Promise<{ default: React.ComponentType }>> = {
  'ai_bridge/agents': () => import('../../../../plugins/ui/pages/brain/ai_bridge/agents/page'),
  'ai_bridge/providers': () => import('../../../../plugins/ui/pages/brain/ai_bridge/providers/page'),
  'ai_bridge/sync': () => import('../../../../plugins/ui/pages/brain/ai_bridge/sync/page'),
  'knowledge/memory': () => import('../../../../plugins/ui/pages/brain/knowledge/memory/page'),
  // ...
};
```

#### Mount-Plugins Changes

Current behavior:
1. Scans plugin sources for page.tsx files
2. Copies full file content to `apps/dashboard/app/{hub}/{path}/page.tsx`
3. Also copies `loading.tsx`, `layout.tsx`, `error.tsx` files
4. Watcher re-copies on any file change

New behavior:
1. Scans plugin sources for page.tsx files
2. Builds slug-to-import-path mapping per hub
3. Reads hub default path from existing redirect config
4. Writes `registry.ts` per hub (one file per hub, not per page)
5. Writes the 6 catch-all `page.tsx` files (identical template)
6. Watcher regenerates registry on page add/delete only
7. Content edits flow through Turbopack natively via the import path in the registry

Old mounted files deleted: all `page.tsx`, `loading.tsx`, `layout.tsx`, `error.tsx` in hub subdirectories.

#### Loading/Layout/Error Handling

The 46 `loading.tsx` files are all passthrough skeleton placeholders. The 25 `layout.tsx` files are all `<>{children}</>` passthroughs. The 2 `error.tsx` files are generic error boundaries.

These are replaced by:
- **Loading:** The `dynamic()` call includes a `loading` prop — each page gets a skeleton during dynamic import
- **Layout:** Hub-level layouts (in `brain/[[...slug]]/` parent) still work. Sub-route layouts were passthrough and add no value.
- **Error:** Error handling moves into the catch-all or into individual page components where needed

#### Tab Registry Validation Fix

`generate-tab-registry.ts` (lines 640-684) validates that each tab's `href` has a corresponding `page.tsx` on the filesystem. This validation must change from checking mounted files to checking registry entries:

Current: `await fs.stat(app/{hub}/{path}/page.tsx)` — will fail since mounted files no longer exist.

New: Check that the slug exists in the hub's `registry.ts` entries, OR check that the source file exists at the plugin path. The tab registry already discovers pages from plugin sources (`discoverPagesFromFilesystem()` at line 178) — the validation should use the same source of truth.

#### How Plugin Lifecycle Works

| Event | What happens |
|-------|-------------|
| **Page added** | Mount-plugins detects new file, regenerates registry.ts for that hub |
| **Page deleted** | Mount-plugins detects removal, regenerates registry.ts |
| **Page edited** | Nothing — Turbopack watches the source via the import path in registry, HMR updates |
| **Page moved** | Registry regenerated — old slug removed, new slug added |

### Phase 3: Cleanup

1. Delete all old mounted page.tsx, loading.tsx, layout.tsx, error.tsx files from hub subdirectories
2. Delete hub-level landing page.tsx files (replaced by optional catch-all with redirect)
3. Remove file-copy logic from mount-plugins

## Risks

| Risk | Mitigation |
|------|-----------|
| Catch-all conflicts with native routes (settings, views, login) | Native routes are in separate top-level directories — no conflict with hub catch-alls |
| Tab registry validation fails (checks mounted page.tsx existence) | Update validation to check source files or registry entries (Phase 1b) |
| 46 loading.tsx skeletons lost | Replaced by `dynamic()` loading prop — equivalent skeleton behavior |
| 25 sub-route layouts lost | All are `<>{children}</>` passthroughs — no functional impact |
| Hub landing redirect breaks (`redirect()` is server-side) | Optional catch-all handles empty slug with client-side `router.replace()`. Phase 3 refinement: move hub landing redirects to `next.config.ts` rewrites to eliminate one-frame flash. |
| `dynamic()` remounts on re-render | Module-level `DynamicCache` map prevents recreating component references |
| Deep linking to specific pages breaks | URL paths unchanged — catch-all resolves same slugs |
| `dynamic()` loading flash on first visit | Loading skeleton placeholder; pages are small after splits (~50-200ms) |
| Production build regression | `dynamic()` without `ssr: false` renders synchronously on server — no visible difference |
| HMR doesn't trigger for source edits | `turbopack.root` is monorepo root + `experimental.externalDir: true` — source files are in watch scope |

## Not In Scope

- Multi-zone architecture (separate Next.js apps per hub)
- Client-side tab routing (replacing Next.js routing with React state)
- API route changes (already consolidated via catch-all proxy)
- `AUGUR_DEV_HUBS` removal (kept as additional optimization for extreme cases)
