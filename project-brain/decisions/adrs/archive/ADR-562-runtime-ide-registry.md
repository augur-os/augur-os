# ADR-562: Runtime IDE Registry

## Context

The unified IDE registry is generated by `apps/dashboard/scripts/generate_registry.py` and consumed by `src/mcp/augur_mcp/registry_loader.py` for context injection. It currently lives at `get_skill_data_dir("ai") / "ide-integration" / "registry.yaml`, which resolves into the external vault.

That placement is wrong for its ownership. The registry changes when generated client surfaces, installed skills, workflows, and command wrappers change. It is operational generated metadata, not user-authored knowledge. Keeping it in the vault creates avoidable vault git churn and mixes runtime mechanics with durable notes, wiki pages, and user data.

Recent vault-cleanup work already moved generated memory assembly, operational reports, attention queues, and compiler mechanics into runtime state. The IDE registry should follow the same storage boundary.

## Decision

Move the canonical generated IDE registry to runtime state:

```text
get_runtime_dir() / "ide-integration" / "registry.yaml"
```

Add explicit path helpers in both path layers:

- `src.config.paths.get_ide_integration_dir()`
- `src.config.paths.get_ide_registry_path()`
- `augur_mcp.config.get_ide_integration_dir()`
- `augur_mcp.config.get_ide_registry_path()`

Update the registry generator to write to `get_ide_registry_path()`. Update the registry loader to read only from `get_ide_registry_path()`. Do not keep a fallback read from the old vault path; stale generated files should not remain a valid source of truth.

Delete the stale vault registry after the migration is verified.

## Consequences

### Positive

- The user vault no longer gets dirty from generated IDE registry churn.
- Runtime ownership is explicit and matches other generated operational artifacts.
- The MCP context injector reads from the same canonical path that the generator writes.
- Stale vault registry files cannot silently mask a missing runtime registry.

### Negative

- Existing local installs need one registry regeneration after upgrading.
- Any out-of-tree scripts that read the old vault path must be updated.

### Neutral

- The registry schema does not change.
- IDE lifecycle settings remain governed by ADR-219.
- Hub and tool scoping principles from ADR-105 remain unchanged.

## Alternatives Considered

### Keep the Registry in the Vault

Rejected. The file is generated operational metadata and changes with local sync state. It should not dirty the user's knowledge vault.

### Move the Registry to Repo Config

Rejected. The file reflects local generated state and installed/client-specific surfaces. Repo config is for versioned system configuration, not local runtime products.

### Read Runtime First, Then Fallback to Vault

Rejected. A fallback would keep the old vault artifact alive as a stale source of truth and make future path bugs harder to detect.
