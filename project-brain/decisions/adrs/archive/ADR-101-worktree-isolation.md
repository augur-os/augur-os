# ADR-101: Worktree Isolation for Parallel Development

## Context

Augur uses git worktrees for parallel ADR implementation (`/implement-adr`) and hub hardening (`/harden`). This allows multiple agents to work on different features simultaneously without branch switching. However, several collision issues have emerged:

### Problem 1: Daemon Monitoring Collisions

The daemon service (`unified_daemon.py`) monitors:
- **Port 3000** for Next.js dashboard health
- **MCP server PIDs** for stalled processes
- **Runtime logs** for error classification

When a worktree runs `npm run dev`, it binds to the same port 3000 as the main repo. The daemon cannot distinguish between:
- Main repo's dev server (should monitor)
- Worktree's dev server (should ignore)

This causes:
- False positive restarts when worktree server stops
- Process cleanup killing the wrong PID
- Notifications for "dashboard down" when worktree intentionally stopped

### Problem 2: MCP Server Path Collisions

The MCP server configuration uses `AUGUR_ROOT` environment variable:

```json
{
  "env": {
    "AUGUR_ROOT": "~/Projects/Augur",
    "PYTHONPATH": "~/Projects/Augur/src/mcp"
  }
}
```

When IDE configs are regenerated by `sync_agents.py` in a worktree:
- Paths point to the worktree directory (correct during work)
- After merge back to main, paths remain worktree-specific (broken)
- MCP tools fail with "file not found" errors

### Problem 3: Instance Lock Contention

The MCP server uses a PID file lock (`instance_lock.py`) to prevent multiple instances:
- Lock file path: `{runtime}/mcp_server.pid`
- Worktree shares the same runtime directory by default
- Two MCP instances cannot run simultaneously

### Problem 4: Path Migration Breakage

During ADR implementation in worktree, agents may:
- Update `AUGUR_ROOT` references for local testing
- Modify `config/system/config.yaml` paths
- Change `.mcp.json` cwd settings

These changes are committed in the worktree. When merged to main:
- Paths now point to non-existent worktree directory
- Main repo breaks: "directory not found" errors
- Debug flow in worktree masked the issue

## Decision

### 1. Worktree Server Isolation

**Use dynamically allocated ports for worktree development:**

| Context | Dashboard Port | MCP Port | Lock File |
|---------|---------------|----------|-----------|
| Main repo | 3000 | 8080 | `{runtime}/mcp_server.pid` |
| Worktree 1 | 3001 | 8081 | `{runtime}/mcp_server_3001.pid` |
| Worktree 2 | 3002 | 8082 | `{runtime}/mcp_server_3002.pid` |
| Worktree N | 3000+N | 8080+N | `{runtime}/mcp_server_{port}.pid` |

**Port Allocation Algorithm:**
```python
def allocate_worktree_port(worktree_path: str) -> dict:
    """Find next available port for new worktree."""
    registry = load_worktree_registry()
    used_ports = {w["dashboard_port"] for w in registry.values()}
    
    for port in range(3001, 3010):  # Max 10 concurrent worktrees
        if port not in used_ports:
            return {
                "dashboard_port": port,
                "mcp_port": port + 5080,  # 8081, 8082, ...
            }
    raise RuntimeError("No available worktree ports (max 10)")
```

**Implementation:**
- Worktree registry tracks active worktrees and their ports
- Startup script requests port from registry
- Sets `PORT` environment variable before `npm run dev`
- MCP config uses port-specific lock file

### 2. Worktree-Aware Daemon Behavior

**Daemon detects worktree context and defers:**

```python
# In dashboard_monitor.py
def get_repo_context():
    """Detect if running in a worktree."""
    result = subprocess.run(
        ["git", "rev-parse", "--show-toplevel"],
        capture_output=True, text=True
    )
    main_repo = subprocess.run(
        ["git", "worktree", "list", "--porcelain"],
        capture_output=True, text=True
    ).stdout.split("worktree ")[1].split("\n")[0]
    
    current = result.stdout.strip()
    is_worktree = current != main_repo
    return {"is_worktree": is_worktree, "path": current, "main": main_repo}
```

**Behavior matrix:**

| Mode | In Main | In Worktree |
|------|---------|-------------|
| **Production** | Monitor + auto-restart | Skip (notify only) |
| **Dev** | Notify only | Skip (silent) |

### 3. Path Sanitization Protocol

**Before merging worktree to main, sanitize paths:**

```bash
# In worktree, before merge:
git diff main --name-only | xargs grep -l "augur-adr\|augur-harden" | while read f; do
  # Replace worktree-specific paths with placeholders
  sed -i '' "s|/augur-adr-[0-9]*|/Augur|g" "$f"
  sed -i '' "s|/augur-harden-[a-z]*|/Augur|g" "$f"
done
```

**Files to check:**
- `*.mcp.json` — cwd, AUGUR_ROOT, PYTHONPATH
- `config/system/*.yaml` — base paths
- `runtime/**/*.json` — offload results (usually gitignored)

### 4. MCP Config Separation

**Worktrees use isolated MCP config:**

```
Source template:
src/config/mcp_worktree.template.json  # Template with $WORKTREE_PATH, $MCP_PORT placeholders

Generated at worktree creation:
worktree/.claude/mcp.json               # From generate-worktree-mcp.py
```

**Template (`src/config/mcp_worktree.template.json`):**
```json
{
  "mcpServers": {
    "augur": {
      "env": {
        "AUGUR_ROOT": "$WORKTREE_PATH",
        "AUGUR_MODE": "dev",
        "MCP_PORT": "$MCP_PORT"
      }
    }
  }
}
```

**Generated at worktree creation:**
```bash
# Generate for all IDEs
python scripts/generate-worktree-mcp.py --path $(pwd) --name adr-{number} --all

# Or generate for specific IDE
python scripts/generate-worktree-mcp.py --path $(pwd) --name adr-{number} --client claude --client cursor
```

**Supported IDE clients:**

| Client | Config Path |
|--------|-------------|
| Claude Code | `.claude/mcp.json` |
| Cursor | `.cursor/mcp.json` |
| Windsurf | `.windsurf/mcp.json` |
| Gemini CLI | `.gemini/settings.json` |
| OpenCode | `.opencode/mcp.json` |
| Agent | `.agent/mcp.json` |

### 5. Worktree Registry

**Track all active worktrees and their allocations:**

**Registry file:** `{runtime}/worktree_registry.yaml`

```yaml
# Auto-managed by generate-worktree-mcp.py
worktrees:
  ~/Projects/augur-adr-098:
    name: adr-098
    dashboard_port: 3001
    mcp_port: 8081
    branch: adr-098-impl
    created_at: 2026-02-13T14:00:00
    status: active
  ~/Projects/augur-harden-finance:
    name: harden-finance
    dashboard_port: 3002
    mcp_port: 8082
    branch: harden-finance
    created_at: 2026-02-14T10:00:00
    status: active
```

**Registry operations:**
```bash
# Register new worktree (allocates port)
scripts/worktree-registry.py register --path $(pwd) --name adr-102

# List active worktrees
scripts/worktree-registry.py list

# Unregister worktree (frees port)
scripts/worktree-registry.py unregister --path $(pwd)

# Get port for current worktree
scripts/worktree-registry.py get-port --path $(pwd)
```

**Concurrent worktree limits:**
- Max 10 concurrent worktrees (ports 3001-3010)
- Registry enforces limit, rejects 11th worktree
- Old worktrees must be removed to free ports

### 6. Workflow Integration

**Update `/implement-adr` and `/harden` skills:**

```markdown
## Phase 0.5: Worktree Isolation Setup

After creating worktree:

1. **Register worktree and allocate port**:
   ```bash
   PORT_INFO=$(scripts/worktree-registry.py register --path $(pwd) --name adr-{number})
   DASHBOARD_PORT=$(echo "$PORT_INFO" | jq -r '.dashboard_port')
   MCP_PORT=$(echo "$PORT_INFO" | jq -r '.mcp_port')
   ```

2. **Set isolated port**:
   ```bash
   echo "PORT=$DASHBOARD_PORT" > .env.local
   ```

3. **Generate isolated MCP config**:
   ```bash
   WORKTREE_PATH=$(pwd) MCP_PORT=$MCP_PORT \
   scripts/generate-worktree-mcp.py > .claude/mcp.json
   ```

4. **Create worktree marker**:
   ```bash
   cat > .augur-worktree.yaml << EOF
worktree: true
dashboard_port: $DASHBOARD_PORT
mcp_port: $MCP_PORT
main_repo: $(git worktree list --porcelain | head -2 | tail -1 | cut -d' ' -f2)
name: adr-{number}
EOF
   ```

5. **Log isolation state**: "Worktree isolated on port $DASHBOARD_PORT (MCP: $MCP_PORT)"
```

**On worktree completion/merge:**
```bash
# Unregister to free port for future worktrees
scripts/worktree-registry.py unregister --path $(pwd)
```

## Consequences

### Positive
- Multiple ADRs can run truly parallel without collisions (up to 10 concurrent)
- Daemon won't interfere with worktree development
- MCP tools work correctly in both contexts
- Clean merge back to main (no path pollution)
- Rollback remains simple (remove worktree, registry frees port)
- Port allocation is automatic, no manual tracking needed

### Negative
- Extra setup step for each worktree (+20 seconds for registry)
- Need to remember different port for each worktree dashboard access
- Slightly more complex MCP configuration
- New files to maintain (registry, worktree template, marker file)
- Registry file must be kept in sync with actual worktrees

### Neutral
- Ports 3001-3010 reserved for worktrees
- `.augur-worktree.yaml` marker file added to `.gitignore`
- `runtime/worktree_registry.yaml` tracks active worktrees

## Alternatives Considered

### Alternative 1: No Worktrees, Sequential Development
**Rejected**: Blocking one ADR until another completes wastes parallel execution capability. ADR-037 autonomous pipeline relies on parallelism.

### Alternative 2: Shared Port, Daemon Smart Detection
**Rejected**: Detecting which process belongs to which worktree via port inspection is unreliable. PIDs can be reused, process names don't indicate context.

### Alternative 3: Separate MCP Instances Per Worktree Always
**Rejected**: Overkill for quick ADRs. Only needed when running MCP tools in worktree context. Most ADR implementation doesn't require MCP.

### Alternative 4: Docker Containers Per Worktree
**Rejected**: Adds heavyweight infrastructure. Git worktrees already provide filesystem isolation. Port isolation is simpler.
