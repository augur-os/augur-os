# Augur Pages — Unified Discovery for Generated, Saved, and Live HTML

## 1. Problem

Three kinds of HTML "pages" exist in Augur today, scattered without a shared discovery surface:

1. **Generated artifacts** — Claude-generated HTML files inside `.superpowers/brainstorm/<id>/content/*.html` (~30+ today). Currently invisible to the user after the session ends.
2. **Saved static HTMLs** — user-curated HTML deliverables under `Au-docs/` (resumes, presentations, collateral, website-working drafts, ~15+ today). No index, no Browse surface.
3. **Live MCP-first dashboard pages** — TSX or YAML config-driven pages discovered via `pluginTabRegistry`, surfaced in Browse via the `dashboard-surfaces` ViewMode.

The user cannot:
- Discover saved or generated HTMLs in Browse.
- Pin any of the three kinds.
- Open static HTMLs from the dashboard with consistent chrome (title, hub, source, "back to Browse").
- Promote a useful brainstorm artifact into durable storage with one action.

This design unifies the three under one Browse ViewMode (`pages`), a sidecar metadata layer, a pin store, and an `/artifact/<slug>` Next.js route.

The design is inspired by Thariq's article on HTML as a richer agent output format than Markdown. It does not adopt Thariq's full S3-publishing flow; Augur stays local-first.

## 2. Goals and non-goals

### Goals
- One Browse ViewMode (`pages`) that discovers all three kinds.
- A `kind` filter pill (`all | live | saved | generated`) on `BrowseToolbar`.
- A stable, deep-linkable URL per static artifact: `/artifact/<slug>`.
- A sandboxed iframe render that preserves Thariq-style two-way interaction (sliders, copy-as-prompt buttons) via `postMessage`.
- A vault-backed pin store (`Au-vault/system/pins.yaml`) and Pinned strip at the top of Browse.
- An explicit `/save artifact` promote flow plus a one-shot bulk-import for the existing scatter.
- Existing scattered HTMLs in `Au-docs/` remain in place; sidecars are added next to them.

### Non-goals
- Brainstorm session viewer dashboard.
- HTML diff / version-control help.
- S3 / external sharing of artifacts.
- Auto-promote heuristic at session end.
- Per-hub pinned sections (the pin store is shaped to feed those later, but the UI is not in this design).
- WYSIWYG artifact editor.

## 3. Concept summary

Every HTML thing the user can read becomes a first-class browseable, pinnable, openable object under one ViewMode. Static HTMLs gain a sidecar (`<file>.meta.yaml`) that carries title/hub/source/tags. Live MCP pages stay discovered through the existing `pluginTabRegistry` and are merged into the same ViewMode. The Browse card carries a `kind` chip; the primary action dispatches `navigate` for live pages and `navigate` to `/artifact/<slug>` for static ones.

## 4. Three kinds, one card

| Kind | Origin | Storage | Open behavior |
|---|---|---|---|
| `live` | MCP-first dashboard page (TSX or YAML config) | `pluginTabRegistry` (existing, generated) | Navigate to existing route (e.g. `/brain/inbox`) |
| `saved` | User-curated HTML (resume, presentation, collateral, exports) | New: `Au-docs/<hub>/artifacts/<slug>.html` + sidecar. Existing scattered files **kept-as-is**, sidecar added next to them. | `/artifact/<slug>` Next.js route with Augur chrome + sandboxed iframe |
| `generated` | Claude-generated, **promoted** out of `.superpowers/brainstorm/...` | Same as `saved` | Same as `saved` |

`kind` shows as a chip on the Browse card. The filter pill toggles `all | live | saved | generated`. The `BrowseItem` schema gains a `metadata.kind` field.

## 5. Data model

### 5.1 Sidecar (`<file>.meta.yaml`)

Lives next to every static HTML in `Au-docs/`. New artifacts are written by `/save artifact`. Existing files get sidecars generated by `artifacts-reindex` with best-guess title (from `<title>` or first `<h1>`) and hub (from path segment).

```yaml
---
slug: spec-onboarding-options
title: "Onboarding screen — 6 directions"
kind: generated          # generated | saved
hub: career              # one of the 9 hubs
source:
  type: brainstorm       # brainstorm | manual | export | import
  session: brainstorm/27346-1777974008  # optional
  origin_path: .superpowers/brainstorm/27346-1777974008/content/spec-written.html
tags: [onboarding, design-exploration]
created_at: 2026-05-08T20:56:00Z
promoted_at: 2026-05-10T14:12:00Z
notes: ""                # free text
---
```

### 5.2 Pin store (`Au-vault/system/pins.yaml`)

```yaml
pins:
  - url: /artifact/spec-onboarding-options
    title: "Onboarding screen — 6 directions"
    kind: generated
    hub: career
    pinnedAt: 2026-05-10T14:30:00Z
  - url: /brain/inbox
    title: "Brain Inbox"
    kind: live
    hub: brain
    pinnedAt: 2026-05-10T14:31:00Z
```

The pin entry is keyed on stable URL. The pin store is single-user, last-write-wins on conflict; writes use the write-rename atomic pattern.

## 6. Storage rules

- **New artifacts** (via `/save artifact`): always written to `Au-docs/<hub>/artifacts/<slug>.html` + sidecar.
- **Existing scattered files** under `Au-docs/career/resumes/`, `Au-docs/venture-augur/...`, `Au-docs/assets/collateral/`, etc.: stay where they are. `artifacts-reindex` generates sidecars in place.
- **Ephemeral** (`.superpowers/brainstorm/<id>/content/*.html`): never indexed unless explicitly promoted.
- **Note-embedded HTMLs** (`Au-vault/notes/.../assets/*.html`, `Au-vault/drafts/.../templates/*.html`): treated as note assets, NOT first-class artifacts. Excluded from indexing unless `artifacts-reindex --include-vault-assets` is passed.

## 7. Open route — `/artifact/<slug>`

### 7.1 Files
- `apps/dashboard/app/artifact/[slug]/page.tsx` — chrome wrapper + iframe
- `apps/dashboard/app/api/artifact/[slug]/raw/route.ts` — file streamer

### 7.2 Chrome bar
Renders above the iframe:
- Title (from sidecar)
- Hub chip (linked to `/<hub>`)
- Source breadcrumb (e.g. "from brainstorm/27346-1777974008")
- **Pin** button (toggles `pin-add` / `pin-remove`)
- **Open external** (opens in new tab)
- **Source folder** link (reveals file in OS via `reveal-file`)

The route only renders artifacts that have a sidecar (i.e. already promoted). Direct rendering of unpromoted `.superpowers/...` HTMLs is out of scope for v1; if added later, it would surface a "Promote" button in this chrome bar.

### 7.3 Iframe
```html
<iframe
  src="/api/artifact/<slug>/raw"
  sandbox="allow-scripts allow-same-origin allow-popups"
  ...
/>
```
A `postMessage` listener on the parent route handles two events from the artifact:
- `{ type: "augur:copy", payload: <string> }` → write to clipboard
- `{ type: "augur:emit", payload: <unknown> }` → toast a confirmation; reserved for future "send to Claude" flows

The artifact's HTML opts in by calling `window.parent.postMessage(...)`. The Augur-design plugin can ship a small JS snippet for artifacts to use.

### 7.4 CSP and headers
The raw endpoint sets `Content-Security-Policy: default-src 'self' 'unsafe-inline' 'unsafe-eval' data: blob:; frame-ancestors 'self'`. Sandbox flags isolate scripts from dashboard auth context. No cookies are forwarded.

## 8. Browse integration

### 8.1 Touch points

| File | Change |
|---|---|
| `apps/dashboard/lib/browse/types.ts` | Rename `dashboard-surfaces` → `pages` in the `ViewMode` union; add `metadata.kind: "live" \| "saved" \| "generated"` to `BrowseItem` |
| `apps/dashboard/lib/browse/viewModeMapping.ts` | Flip `LEGACY_VIEW_MODE_MAP` so `dashboard-surfaces → pages` (back-compat for old URLs) |
| `apps/dashboard/lib/browse/transforms.ts` | Extend `transformPages()` to merge two sources: `pluginTabRegistry` (live) + `artifacts-list` MCP (saved + generated). Each entry tagged with `kind`. |
| `apps/dashboard/app/(views)/browse/BrowseToolbar.tsx` | Kind filter pill (4 chips) |
| `apps/dashboard/app/(views)/browse/BrowseContentGrid.tsx` | Kind chip badge on each card; primary action dispatches `navigate` to existing route for `live`, `navigate` to `/artifact/<slug>` for `saved`/`generated` |
| `apps/dashboard/app/(views)/browse/useBrowseState.ts` | Render Pinned strip at top of grid (reads `pin-list` MCP) |

### 8.2 Back-compat
`?category=dashboard-surfaces` continues to resolve to the new `pages` ViewMode via `LEGACY_VIEW_MODE_MAP`. No external link rot.

### 8.3 Default sort
Within the unified `pages` ViewMode the grid sorts by:
1. Pinned items (in `pins.yaml` order)
2. Then `updated_at desc` (sidecar `promoted_at` for static; tab registry mtime for live)

Per Augur Rule 11 the dashboard talks only through MCP; the merged list is fetched once via the existing `useMcpQuery` plumbing in `useBrowseState`.

## 9. New MCP tools (six, all small)

All Python, registered through the existing MCP server scaffolding.

| Tool | File | Purpose |
|---|---|---|
| `save-artifact` | `src/mcp/tools/artifacts.py` | Promote one HTML — copies/moves file, writes sidecar, returns slug |
| `artifacts-reindex` | `src/mcp/tools/artifacts.py` | Scan `Au-docs/**/*.html`; generate missing sidecars; refresh index |
| `artifacts-list` | `src/mcp/tools/artifacts.py` | Return all known artifacts in Browse-card shape |
| `pin-add` | `src/mcp/tools/pins.py` | Append entry to `pins.yaml` (write-rename atomic) |
| `pin-remove` | `src/mcp/tools/pins.py` | Drop entry by URL |
| `pin-list` | `src/mcp/tools/pins.py` | Return pin list |

Per the capability policy table in `CLAUDE.md`, all six are exposed as `cli via shell` by default. The dashboard reaches them through the existing `POST /api/mcp/tool` plumbing.

## 10. Registration flow

### 10.1 `/save artifact` extension

```
/save artifact <source-path> [--hub <name>] [--slug <slug>] [--title "..."] [--tags a,b,c]
```

Behavior:
- Read source HTML (path may be inside `.superpowers/`, anywhere on disk, or already inside `Au-docs/`)
- Hub: from `--hub`, else inferred from current session context, else inferred from path
- Slug: from `--slug`, else from sluggified `--title`, else from filename
- Title: from `--title`, else from `<title>` tag, else from first `<h1>`, else from filename
- Move (or copy if source is outside the repo) to `Au-docs/<hub>/artifacts/<slug>.html`
- Write sidecar with full provenance (`source.type = brainstorm` if path matched `.superpowers/brainstorm/`, else `manual`)
- Call `artifacts-reindex --slug <slug>` for single-entry refresh

The `/save` command extension lives where the existing `/save` skill is anchored (likely `shared-vault/skills/save/commands/save.md`); the actual implementation calls the new `save-artifact` MCP tool.

### 10.2 One-shot backlog migration

```
augur artifacts reindex --import ".superpowers/brainstorm/*/content/*.html" --hub auto --dry-run
augur artifacts reindex --import ".superpowers/brainstorm/*/content/*.html" --hub auto --commit
augur artifacts reindex     # picks up existing Au-docs/** files, generates sidecars in place
```

`--hub auto` derives hub from session context or path heuristic. For the brainstorm imports, the user reviews generated sidecars (single edit pass) and reruns reindex. Files are copied into `Au-docs/<hub>/artifacts/` (originals stay in `.superpowers/` until that brainstorm directory is cleaned).

## 11. Phasing

### Phase 0 — backlog migration (one-shot)
Run `artifacts-reindex --import` against `.superpowers/brainstorm/`. Run `artifacts-reindex` against `Au-docs/`. User reviews generated sidecars and edits hub/title/tags as needed.

### Phase 1 — Browse rename + open route
- `dashboard-surfaces` → `pages` ViewMode rename + legacy alias.
- `transformPages()` merge of two sources.
- `BrowseToolbar` kind filter pill.
- `BrowseContentGrid` kind chip badge.
- `/artifact/[slug]` route + `/api/artifact/[slug]/raw` endpoint.
- `/save artifact` command extension.

### Phase 2 — pin store and Pinned strip
- `pin-add` / `pin-remove` / `pin-list` MCP tools.
- Pin button on artifact chrome and on Browse card hover.
- Pinned strip at top of `BrowseContentGrid` reading from `pin-list`.

Each phase is independently shippable. Phase 1 unblocks discovery; Phase 2 layers the pin UX.

## 12. Testing

Per Augur Rules 19, 28, 29 — all runs through loops/slash commands:

- **Python** (`/auto-test-pytest`): sidecar parser, slug derivation, `artifacts-list` shape, pin atomicity (write-rename), `--import` glob matching.
- **TypeScript** (`/auto-test-build`): `transformPages()` merge of two sources, `viewModeMapping` legacy alias, kind chip rendering.
- **Dashboard** (`/auto-test-dashboard`): `/browse?category=pages` and `/browse?category=dashboard-surfaces` both load; `/artifact/<known-slug>` loads to interactive state.
- **Browser verification** (Rule 28, Chrome MCP):
  - Browse `pages` mode shows kind chips and the kind filter narrows the grid.
  - `/artifact/<slug>` renders Augur chrome + iframe; iframe scripts execute (sandbox flags allow).
  - Pin button on chrome toggles `pins.yaml` and a pinned card appears at top of Browse.
  - `/save artifact` promotes a file; the new artifact appears in Browse without a manual reload.

## 13. Risks and open questions

| Risk | Mitigation |
|---|---|
| Sidecar drift (file renamed/moved without updating sidecar) | `artifacts-reindex` detects orphan sidecars (sidecar exists but HTML missing) and orphan HTMLs (HTML exists but sidecar missing); reports both. |
| `transformPages()` already 1045 lines; adding a merge path grows it | Extract the merge into a small helper file `lib/browse/pages-merge.ts`. Per the existing `TODO_CLEANUP` marker in `transforms.ts`, this is incremental progress, not new debt. |
| Iframe sandbox blocks a use case Thariq's article wants | The `postMessage` channel covers clipboard and "emit"; if a future use case needs more (e.g. fetch from an MCP), revisit sandbox flags then, not now. YAGNI. |
| Slug collision (two HTMLs slug to the same value) | `save-artifact` enforces uniqueness within a hub; collisions append a `-N` suffix and warn. |
| Existing scattered files have stale or wrong path-derived hubs | `artifacts-reindex` runs `--dry-run` first; user reviews and edits sidecars before commit. |
