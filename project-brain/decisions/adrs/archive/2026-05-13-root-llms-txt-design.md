# Root `llms.txt` and `llms-full.txt` for Repo Self-Description

## 1. Problem

When an AI agent — any client: Claude Code, Codex, Gemini CLI, Cursor, Copilot, or a passing one-off model — first lands in the Augur repository, it has **no concise repo doc map optimized for an LLM context window**. The repo contains rich material (595 ADRs, 11 agent-topic docs, references, guides) but the AI client has to discover it ad-hoc.

The per-client constitution files (`CLAUDE.md`, `CODEX.md`, `AGENTS.md`, `.cursor/rules/augur.mdc`, `.github/copilot-instructions.md`, `.gemini/GEMINI.md`) are intentionally **client-specific** and configured via ADR-670 (Cross-Client Bundle Architecture). They do not serve as a generic, client-neutral repo map.

The emerging `llms.txt` / `llms-full.txt` convention is the right shape for that missing map. The user already has the `geo-llmstxt` plugin installed (a tool that **analyzes** other sites' files of this kind), but Augur does not currently **author** its own root-level files.

## 2. Goals

- Author and commit `llms.txt` at the repo root: a concise (target ≤ 5 KB) pointer map covering README, ROADMAP, agent-topic docs, architecture overview, ADR index, and key reference docs.
- Author and commit `llms-full.txt` at the repo root: the concise map plus **inlined** copies of `agent-rules.md`, `architecture-overview.md`, and `what-is-augur.md` (target ≤ 50 KB).
- Files are **generated**, not hand-edited. The source is `sync_agents` + a curated header template.
- `sync_agents check` reports stale `llms.txt` / `llms-full.txt` as a lint failure (same drift discipline as `CLAUDE.md`).
- Both files survive `sync_agents purge --confirm` (they are managed artifacts, regenerated on next sync).

## 3. Non-Goals

- Not replacing per-client constitution files. Those are kept and continue to be the source of truth for client-specific rules.
- No cloud hosting; files stay at the repo root.
- No schema-strict validation of the body — `llms.txt` is intentionally flexible. We assert generator output shape via tests, not via an external schema.
- No live generation at request time. Static files in the repo, regenerated by `sync_agents`.
- No use of the existing `geo-llmstxt` plugin — that one analyzes external sites; this work authors Augur's own files.

## 4. Design

### 4.1 Generator location and entry points

| File | Purpose |
|---|---|
| `shared-vault/skills/ai/scripts/sync_agents/llms_txt.py` | Generator module: builds `llms.txt` and `llms-full.txt` content from sources. |
| `shared-vault/skills/ai/scripts/sync_agents/__init__.py` | Add a new generator call inside the existing `sync agents` pipeline, immediately after the per-client constitution generators run (they share input sources). |
| `shared-vault/skills/ai/assets/templates/llms-txt-header.md` | Hand-curated header committed once: one-paragraph Augur description + BYO-AI-client model + "where to look next" pointers. Stable; rarely changes. |
| `shared-vault/skills/ai/assets/templates/llms-full-txt-header.md` | Hand-curated header for the full variant. |

### 4.2 `llms.txt` body layout

```
# Augur — Local Second Brain for Your AI Clients

<hand-curated header from llms-txt-header.md — 1 paragraph>

## Entry points

- README.md — repository overview
- ROADMAP.md — release roadmap
- docs/what-is-augur.md — Augur vs. agents vs. LLM wrappers
- docs/architecture-overview.md — the Harness, 5 layers, runtime substrate

## Agent topics (load on demand)

- docs/agent-topics/agent-rules.md — global agent instructions
- docs/agent-topics/ARCHITECTURE.md — file structure, paths, plugin mounting
- docs/agent-topics/CODING.md — code, commits, style
- ... (auto-generated from glob; one line per file with one-line purpose extracted from H1/first paragraph)

## ADRs

- docs/adrs/adrs-index.json — central JSON index of 595 ADRs
- docs/generated/adr-index.md — human-readable status summary

## References

- docs/references/surface-decision-matrix.md — canonical surface assignments
- docs/references/agent-vs-mcp-checklist.md
- docs/references/design-standards.md
```

### 4.3 `llms-full.txt` body layout

```
<llms.txt contents>

---

## Inlined: docs/agent-topics/agent-rules.md

<full file body>

---

## Inlined: docs/architecture-overview.md

<full file body>

---

## Inlined: docs/what-is-augur.md

<full file body>
```

### 4.4 Generation algorithm

1. Read header template files.
2. Glob `docs/agent-topics/*.md` (skip `agent-rules.md` — handled separately to highlight as canonical).
3. For each agent-topic file, extract the H1 title + first prose paragraph for the one-line purpose (reuse `_first_prose_paragraph` from `src.lib.adr_utils` if shape allows; else implement a sibling).
4. Compose `llms.txt`. Write to repo root.
5. Compose `llms-full.txt`: `llms.txt` content + separators + inlined bodies of `agent-rules.md`, `architecture-overview.md`, `what-is-augur.md`.
6. Both files write via `src.lib.generated_artifacts.write_stable_text` (existing helper used by other generators; ensures stable output for `sync_agents check`).

### 4.5 `sync_agents check` integration

`sync_agents check` (existing subcommand) compares disk content with regenerated content. Both `llms.txt` and `llms-full.txt` are added to its file set. Stale = `check` returns non-zero, which is exactly what CI consumes today for other generated agent surfaces.

### 4.6 Purge behavior

The two files are listed in the sync_agents managed-artifact registry. `sync_agents purge --confirm` removes them; the next `sync` call regenerates them. Same lifecycle as per-client constitution files.

## 5. Boundary

- No direct LLM calls in generation. Pure text composition.
- No external HTTP fetches.
- File writes use the path helpers and the existing `write_stable_text` helper.
- Generator is pure-Python stdlib + PyYAML (already a Augur dependency).

## 6. Open Questions

| # | Question | Tentative answer |
|---|---|---|
| 1 | Should ADR list be inlined in `llms.txt` too? | No — too long. Pointer to the index is sufficient. |
| 2 | Should `llms.txt` link to public website (`augur.run`)? | Yes, in the header. |
| 3 | Should `llms-full.txt` inline the surface-decision-matrix? | Defer — measure first. Add in a follow-up if AI clients ask for it. |
| 4 | Should the file include a SHA or version stamp? | No — `sync_agents check` already enforces freshness; a SHA would force needless churn on every commit. |

## 7. Acceptance criteria (mirrored in the plan)

- [ ] `llms.txt` committed at repo root and visible from `ls`.
- [ ] `llms-full.txt` committed at repo root.
- [ ] `sync_agents check` reports clean.
- [ ] Hand-editing either file and re-running `sync_agents check` reports stale (drift detection works).
- [ ] Header templates committed under `shared-vault/skills/ai/assets/templates/`.
- [ ] Tests verify: header inclusion, agent-topic enumeration, inline section presence, stable output across two consecutive runs.
- [ ] Both files pass a 5KB / 50KB size sanity check (warnings if exceeded; not hard failures).
