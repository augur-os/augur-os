# ADR-442: Cowork Plugin Integration [RECONSTRUCTED]

## Context

Claude Cowork supports personal plugins that extend Claude's capabilities in a team workspace. Augur's skills, knowledge, and MCP tools were not accessible from Cowork because there was no sync adapter to assemble a Cowork-compatible plugin package. A legacy `export_cowork_plugin.py` script existed but was disconnected from the sync engine and produced an incorrect directory structure.

## Decision

Integrate Augur into Claude Cowork as a single personal plugin via a new sync adapter, using thin-plugin + fat-MCP architecture. The adapter lives within the existing `sync_agents` system alongside Claude Code, Cursor, Codex, and Gemini adapters.

### Sync Adapter

A `CoworkAdapter` class in `.claude/skills/ai_bridge/scripts/sync_agents/adapters/cowork.py` discovers user-facing skills from all master clients, transforms SKILL.md files to domain-oriented format, and assembles a complete Cowork plugin package at `dist/plugins/augur-cowork/`.

### Plugin Output Structure

```
dist/plugins/augur-cowork/
+-- .claude-plugin/plugin.json
+-- .mcp.json
+-- skills/
+-- commands/
    +-- ask.md
    +-- search.md
    +-- save.md
```

The plugin is flat at the output root -- no nested `plugins/` directory.

### Skill Filtering

Only user-facing skills from the `brain`, `career`, `life`, and `studio` hubs are included. Infrastructure skills (`ai_bridge`, `daemon`, `renderer`, etc.), dev-prefixed skills (`dev-build`, `dev-test`), and auto-prefixed skills (`auto-lint`, `auto-fix`) are excluded.

### SKILL.md Transformation

Each included SKILL.md is transformed for Cowork consumption:
- `x-augur-*` frontmatter fields are stripped (only `name` and `description` kept)
- Slash command references (`/career`, `/search`) are removed
- Absolute paths (`/Users/...`) are removed
- Dev-only code blocks (git, pytest, npm test) are stripped
- An `AUGUR-ADAPTED-COPY` marker with source client is injected
- Template overrides in `cowork_templates/` can provide richer domain-oriented instructions

### MCP Server Integration

- `cowork` added to `CLIENT_CAPABILITIES` in `context_manager.py` with `LIMITED` capability level
- `COWORK_VISIBLE_TOOLS` filter in `client_surface.py` exposes knowledge/search/file tools while hiding dev/admin tools
- New `augur-list-capabilities` MCP tool returns available domains and descriptions for Cowork Claude to understand capabilities at conversation start

### MCP Config

The generated `.mcp.json` points to the Augur MCP server with `--client-id cowork`, ensuring cowork-specific tool filtering is applied.

### Legacy Deprecation

The `export.py` module in `dist/plugins/augur-system/skills/import/augur/lib/modes/` was deprecated with a message directing users to the cowork sync adapter. The legacy `export_cowork_plugin.py` script was deleted.

## Consequences

### Positive

- Augur's knowledge and productivity tools are accessible from Claude Cowork
- Plugin is auto-generated by the sync engine -- stays in sync with skill changes
- Domain-oriented SKILL.md transformation makes instructions clearer for Cowork Claude
- Thin-plugin architecture: all AI execution happens via MCP, not in the plugin

### Negative

- New adapter to maintain in the sync engine
- Cowork tool filtering (`COWORK_VISIBLE_TOOLS`) must be updated when new user-facing tools are added
- Template overrides require manual authoring for key skills

### Neutral

- Plugin structure follows Cowork's `.claude-plugin/plugin.json` + `.mcp.json` convention
- Existing sync engine patterns (BaseAdapter, skill discovery, managed files) are reused
- Commands (`ask`, `search`, `save`) provide entry points for Cowork users

## Alternatives Considered

### Alternative 1: Manual Plugin Export Script

Keep the legacy `export_cowork_plugin.py` as a standalone script.

**Rejected because**: It was disconnected from the sync engine, produced incorrect directory nesting, and required manual invocation. The adapter integrates with `sync_agents --all` for automatic updates.

### Alternative 2: Full Skill Copy Without Transformation

Copy SKILL.md files verbatim into the Cowork plugin.

**Rejected because**: Skills contain slash command references, absolute paths, and dev-only instructions that confuse Cowork Claude. Transformation produces cleaner, domain-oriented instructions.

### Alternative 3: Separate MCP Server for Cowork

Run a dedicated MCP server instance with a different tool set.

**Rejected because**: Duplicates infrastructure and complicates deployment. The `--client-id cowork` flag with per-client tool filtering achieves the same result with a single MCP server.
