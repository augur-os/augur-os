# ADR-746: Root `llms.txt` and `llms-full.txt` for Repo Self-Description

## Status

Implemented (2026-05-13).

## Context

When an AI agent (any client — Claude Code, Codex, Gemini, Cursor, Copilot, or a passing one-off model) first lands in the Augur repository, it has no concise doc map optimized for an LLM context window. The repo has rich documentation — 586 ADRs, 11 agent-topic docs, references, guides — but no single client-neutral entry point.

`CLAUDE.md`, `CODEX.md`, `AGENTS.md`, etc., are client-specific **constitution** files (ADR-670, the Cross-Client Bundle Architecture). They are intentionally targeted at one client. They do not double as a generic repo map.

The emerging `llms.txt` / `llms-full.txt` convention (the user's installed `geo-llmstxt` plugin analyzes other sites' files of this kind) is the right shape for the missing repo-level map. Augur should publish its **own** `llms.txt` so any AI client landing in the repo can ground itself in a few thousand tokens.

## Decision

Generate two files at the repo root, kept in sync by `sync_agents`:

- **`llms.txt`** — concise pointer map (target: ≤ 5 KB)
- **`llms-full.txt`** — pointer map with the load-bearing agent topic docs inlined (target: ≤ 50 KB)

Both files are committed to the repo. They are **generated**, not hand-edited; the source is `sync_agents` + a curated header template.

Concretely:

1. Generator lives in `shared-vault/skills/ai/scripts/sync_agents/` (which already owns the per-client harness generators).
2. `llms.txt` body lists:
   - `README.md`, `ROADMAP.md` with one-line purpose
   - `docs/what-is-augur.md`, `docs/architecture-overview.md`
   - Every `docs/agent-topics/*.md` with one-line purpose (per ADR-730's 11-topic catalog)
   - Pointer to `docs/adrs/adrs-index.json` for ADR discovery
   - Pointer to the canonical surface-decision-matrix and reference docs
3. `llms-full.txt` is `llms.txt` plus inlined `docs/agent-topics/agent-rules.md`, `architecture-overview.md`, and `what-is-augur.md`.
4. Hand-curated header at top of each file (committed in `shared-vault/skills/ai/assets/templates/`) explains: what Augur is in one paragraph, the BYO-AI-client model, and where to look next.
5. `sync_agents` runs the generator on every invocation; lint fails if the files are stale relative to source.
6. The existing third-party `geo-llmstxt` plugin (which analyzes other sites' files) is **unrelated** — that one is a website-audit tool. This ADR authors Augur's own repo-root files.

## Non-Goals

- No replacement of `CLAUDE.md` / `CODEX.md` / `AGENTS.md` / `.cursor/rules/augur.mdc` / `.github/copilot-instructions.md`. Those are per-client constitution files; `llms.txt` is the client-neutral repo map.
- No cloud hosting. Files in the repo only.
- No schema enforcement beyond what `sync_agents` lints — `llms.txt` is intentionally flexible.
- No live document generation at request time. Static files in the repo, regenerated by `sync_agents`.

## Consequences

- Two new generated files at repo root (`llms.txt`, `llms-full.txt`).
- `sync_agents` gains a generator step; existing sync test suite extends to cover it.
- Any AI client wandering into the repo grounds itself in 2-5 KB without hunting through `docs/`.
- Drift detection: stale `llms.txt` flunks lint, just like stale `CLAUDE.md` does today.

## Related

- ADR-670 (cross-client bundle architecture — `llms.txt` is the client-neutral peer of the per-client constitution files)
- ADR-730 (11 agent-topic docs that `llms.txt` indexes)
- `sync_agents` (the generator pipeline)


## Amendment — 2026-05-31: budget raised to 96 KB and generator-enforced

The original "≤ 50 KB" target for `llms-full.txt` proved unsatisfiable for this
ADR's own intent: the three curated load-bearing docs (`agent-rules.md`,
`architecture-overview.md`, `what-is-augur.md`) alone reached ~50 KB, leaving no
room to inline all three in full. Two changes resolve this:

1. The budget is now **enforced by the generator** (`sync_agents/llms_txt.py`),
   not by a test tripwire. `_compose_full` inlines the docs in priority order and
   gracefully truncates the lowest-priority body — with a pointer to the complete
   file — if the budget would be exceeded, so the output is bounded by
   construction and human-authored docs can grow without breaking generation.
2. The ceiling is raised from 50 KB to **96 KB** (`LLMS_FULL_TXT_MAX_BYTES`),
   which holds the current curated set in full (~53 KB) with generous headroom
   and stays trivially consumable by modern AI clients.
