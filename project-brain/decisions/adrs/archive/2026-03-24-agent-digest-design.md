# Agent Digest: Layered Nightly Summary for Agent Decision Compliance

**Date:** 2026-03-24
**Status:** Draft
**Skill:** `skills/auto-agent-digest/`

## Problem

Agents repeatedly violate long-term decisions despite the existence of memory entries (41), ADRs (349), daily logs, and CLAUDE.md rules (22). The root cause: agents load CLAUDE.md rules and a MEMORY.md index at session start, but never see ADR bodies, memory entry content, or accumulated session learnings unless they explicitly search. Decisions exist but aren't surfaced at the moment of relevance.

Three failure modes, all equally painful:

1. **Retired pattern reintroduction** — agent proposes something an ADR explicitly killed (e.g., centralized registry, ADR-163)
2. **Preference/feedback violation** — agent adds emojis, uses fallbacks instead of root-cause fixes, mocks databases
3. **Missed recent changes** — agent doesn't know about a migration or architectural shift from the last 2 weeks

## Solution: Layered Digest with Event Journal

A nightly auto-loop that collects violation signals, scores decisions by violation frequency, and compiles a token-capped digest into the top of MEMORY.md — the one file already auto-loaded by every agent on every platform.

### Architecture Overview

```
Signal Collectors              Journal              Compiler              Output
┌──────────────────┐     ┌──────────────────┐   ┌───────────────────┐   ┌──────────────┐
│ Git scanner      │────▶│                  │   │                   │──▶│ MEMORY.md    │
│ Session log      │────▶│ events.jsonl     │──▶│ compile_digest.py │   │ Hot section  │
│ /flag command    │────▶│ (append-only)    │   │                   │──▶│ Warm section │
└──────────────────┘     └──────────────────┘   └───────────────────┘   └──────────────┘
                                                         │
                                                         ▼
                                                 compile_digest.py writes
                                                 digest-hot.md + digest-warm.md
                                                         │
                                                         ▼
                                                 memory_assembler.py prepends
                                                 digest files when generating MEMORY.md
                                                 (distribute to all agents)
```

**Token budgets:**
- Hot tier: 500 tokens (~10-15 directives), 7-day window
- Warm tier: 500 tokens (~8-12 decisions), 30-day window
- Total adaptive: ~1,000-1,500 tokens, scaling down as violations decrease
- Empty Hot tier: single line `No active directives — all patterns clean this week.`

## Event Journal

Append-only JSONL file at `{runtime_dir}/agent-digest/events.jsonl`.

### Collector 1: Git Scanner

Runs in nightly loop. Scans last 24h of commits for known anti-patterns.

```jsonl
{"ts": "2026-03-24T02:00:00Z", "source": "git", "type": "pattern_violation", "rule": "rule_11_no_fs", "evidence": "commit abc123 added 'import fs' in apps/dashboard/", "commit": "abc123", "author": "agent:claude-code"}
```

Patterns scanned (defined in `assets/violation-patterns.yaml`):
- `import fs` / `import { readFile }` in `apps/dashboard/` → rule #11
- `@ts-ignore` / `eslint-disable` / `@pytest.mark.skip` → rule #5
- Edits to files with `AUTO-GENERATED` header → memory: never-edit-generated-files
- `pluginFallback` improvements without fixing primary path → rule #5
- Centralized registry additions → rule #2 / ADR-163

### Collector 2: Session Log Parser

Runs in nightly loop. Scans agent session logs for correction signals.

```jsonl
{"ts": "2026-03-24T14:30:00Z", "source": "session_log", "type": "user_correction", "signal": "user said 'no don't mock the database'", "rule": "inferred:testing_pattern", "session": "claude-code-2026-03-24"}
```

Signals detected:
- Phrases like "no", "don't", "stop", "wrong", "I said" near a decision reference
- Hook rejections (pre-commit failures indicating violated patterns)
- Explicit `/flag` invocations

### Collector 3: `/flag` Command

```
Usage: /flag "<description>" [--rule <rule_id>] [--adr <ADR-NNN>]

Examples:
  /flag "agent added to centralized config again" --adr ADR-163
  /flag "used emoji in commit message"
  /flag "edited generated file directly"
```

Appends a manual event with boost priority. If `--rule`/`--adr` provided, maps directly. Otherwise inferred from description text against `directive-map.yaml`.

```jsonl
{"ts": "2026-03-24T10:15:00Z", "source": "manual", "type": "flag", "rule": "ADR-163", "note": "agent added to centralized config again", "priority": "boost"}
```

### Journal Lifecycle

- Append-only, never edited in-place
- Nightly loop reads, scores, archives processed entries to `events.{date}.jsonl.gz`
- Retention: 30 days of archives, then purge
- Location: `{runtime_dir}/agent-digest/` (runtime state, not in project tree — rule #4)

## Scoring Algorithm

### Hot Tier Scoring

```
score(directive) = sum(event_weights) * recency_decay * boost_multiplier
```

**Event weights:**

| Event type | Weight | Rationale |
|-----------|--------|-----------|
| `user_correction` | 5 | Highest — user had to intervene |
| `manual_flag` | 4 | Explicit user signal |
| `git_pattern_violation` | 3 | Concrete code evidence |
| `hook_rejection` | 2 | Automated catch |

**Recency decay:**

| Age | Multiplier |
|-----|-----------|
| 0-2 days | 1.0x |
| 3-5 days | 0.7x |
| 6-7 days | 0.4x |
| >7 days | 0.0 (drops off Hot tier) |

**Boost multipliers:**
- Manual `/flag` with boost: 1.5x
- Repeated violation (3+ in window): 1.3x

### Directive Lifecycle

1. **First violation**: enters journal, scored, may or may not make the cut
2. **Repeated violations**: score increases, rises in ranking
3. **No violations for 7 days**: drops off Hot tier
4. **No violations for 30 days**: pattern learned — removed from consideration
5. **30+ days in Hot with no decrease**: generate a promotion candidate notification (via `attention` skill) for operator review — the edit target is `docs/agent-topics/agent-rules.md` (CLAUDE.md source), never CLAUDE.md directly (it's auto-generated)

### Compilation Steps

**Hot tier (nightly):**
1. Read all events from last 7 days
2. Group by directive (map events to CLAUDE.md rules, ADR numbers, or memory entry IDs via `directive-map.yaml`)
3. Score each directive
4. Rank by score, take top-N within 500 token cap
5. Format as terse imperative bullets with violation count and source reference
6. Write to `{memory_dir}/digest-hot.md`

**Warm tier (weekly):**
1. Scan ADR vault for ADRs modified/created in last 30 days
2. Extract title + one-line summary from frontmatter
3. Sort by date descending
4. Cap at 500 tokens
5. Write to `{memory_dir}/digest-warm.md`

### Directive-to-Rule Mapping

Lives in `skills/auto-agent-digest/assets/directive-map.yaml`:

```yaml
directives:
  no_fs_in_dashboard:
    label: "NO fs/spawn in dashboard"
    sources: ["rule_11", "ADR-453"]
    patterns: ["import fs", "import { readFile", "execSync", "spawn"]
    scope: "apps/dashboard/"

  no_fallback_fixes:
    label: "NO fallback-path fixes"
    sources: ["rule_5", "ADR-453"]
    patterns: ["pluginFallback", "fallbackData"]
    scope: "apps/dashboard/"

  no_generated_edits:
    label: "NO generated file edits"
    sources: ["memory:never-edit-generated-files"]
    patterns: ["AUTO-GENERATED"]
    scope: null  # any file
```

Grows over time as new violations are detected.

### Auto-Loop Registration

SKILL.md frontmatter:

```yaml
x-augur-type: autoloop
x-augur-hub: adaptive
x-augur-commands: [flag]
x-augur-dependencies:
  optional: [attention]  # cross-hub (life) — used for operator promotion notifications
x-augur-loop:
  name: auto-agent-digest
  tier: 1
  trigger: nightly
```

**Difficulty levels** (documented in SKILL.md body, not frontmatter):

| Level | Behavior |
|-------|----------|
| d=0 | Collect signals only — append to journal, report stats, no MEMORY.md write |
| d=1 | Collect + compile Hot tier, write to MEMORY.md |
| d=2 | Full run — collect, compile both tiers, distribute to all agent targets, archive old journal entries |

### `/flag` Command Execution Chain

`commands/flag.md` defines the slash command interface. When invoked, it calls `scripts/flag.py` which:
1. Parses `--rule` and `--adr` flags
2. If no explicit mapping, infers directive from description text against `directive-map.yaml` labels
3. Appends JSONL event to `{runtime_dir}/agent-digest/events.jsonl` with `priority: "boost"`

Registration: declared in SKILL.md frontmatter via `x-augur-commands: [flag]` — no centralized config edit (rule #2).

### Execution Flow (d=2)

```
1. collect_git_signals.py      → events.jsonl (append)
2. collect_session_signals.py  → events.jsonl (append)
3. compile_digest.py --tier hot   → {memory_dir}/digest-hot.md
4. compile_digest.py --tier warm  → {memory_dir}/digest-warm.md
5. memory_assembler.py assemble   → prepends digest files into MEMORY.md, then distributes
6. Archive events older than 24h  → events.{date}.jsonl.gz
7. Purge archives older than 30 days
```

### Distribution & MEMORY.md Write Ownership

**Problem:** `memory_assembler.py` regenerates MEMORY.md from scratch during its normal operation. If `compile_digest.py` writes directly to MEMORY.md, the next `auto-memory-sync` run would overwrite the Hot/Warm sections.

**Solution:** `compile_digest.py` writes to intermediate files (`digest-hot.md`, `digest-warm.md`) in the memory directory. `memory_assembler.py` is modified to check for these files and prepend them when generating MEMORY.md. This requires a small change to `memory_assembler.py` — add a `_prepend_digest_sections()` step to the assembly pipeline.

**Write ownership:**
- `compile_digest.py` owns `digest-hot.md` and `digest-warm.md` (intermediate files)
- `memory_assembler.py` owns `MEMORY.md` (final output) — it reads digest files and prepends them
- Run order: `compile_digest.py` runs first (step 3-4), then `memory_assembler.py` (step 5)

**Implementation scope:** Modifying `memory_assembler.py` to prepend digest sections is part of this skill's implementation. Estimated change: ~20 lines — read digest files if they exist, prepend before the Memory Index header.

## Evolution Model

Per CLAUDE.md rule #8: auto-loops must evolve.

| Level | Evolution signal |
|-------|-----------------|
| d=0 | "Found 0 events" for 7 consecutive days → flag: session log collector may be broken |
| d=1 | All Hot directives score < 2 → `evolution_gap`: "Hot tier under-populated — review directive-map.yaml for missing patterns" |
| d=2 | Hot tier empty for 14 days → propose graduating to d=3 |

**d=3 (future, auto-proposed):** Pattern discovery mode.
- Read recent user corrections from session logs
- Cluster into candidate directives
- Propose new entries for `directive-map.yaml` via attention notification
- Operator approves/rejects before they enter scoring

**Promotion/retirement:**
- Directive in Hot 30+ days with no decrease → generate promotion candidate notification (via `attention` skill) for operator review, targeting `docs/agent-topics/agent-rules.md` as the edit source
- Directive drops off Hot and never returns → pattern learned, archive

## Success Criteria

1. Within 2 weeks: agents reference Hot directives in their reasoning when making decisions that touch flagged patterns
2. Violation frequency for top-5 directives decreases by 50% within 30 days
3. New ADRs from last 2 weeks appear in Warm tier — agents stop proposing patterns that recent ADRs retired
4. Token budget stays under 1,500 total across both tiers
5. `/flag` provides immediate feedback loop — flagged violation appears in next nightly digest
