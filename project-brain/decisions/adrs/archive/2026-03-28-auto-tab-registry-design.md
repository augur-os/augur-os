# auto-tab-registry Scanner Design

**Date:** 2026-03-28
**Status:** Draft
**Approach:** A — Python scanner reading generated-registry.ts

## Problem

The `templates` hub was missing its `[[...slug]]/` catch-all route directory, causing the tab registry validation in `generate-tab-registry.ts` to fail with "1 tab(s) have no corresponding page.tsx." This killed the dev server with no auto-recovery. No existing scanner validates tab-to-page resolution before the build runs.

### Gap Analysis

| Scanner | What it checks | Why it misses tab orphans |
|---------|---------------|--------------------------|
| auto-page-mounts | Old `contributions.pages` source files | Doesn't validate ADR-218 filesystem-discovered tabs |
| auto-code-health | `tsc --noEmit` | Doesn't run full build pipeline |
| auto-test-build | `npm run build` exit code | Runs build but doesn't parse specific errors |
| auto-test-pages | HTTP 200 on routes | Runtime-only, can't catch build failures |
| auto-dead-wiring | Skill registry declarations | Wrong domain — validates skills, not tabs |

## Solution

A new `auto-tab-registry` scanner that validates every tab in the generated registry has a resolvable page before the build runs.

## Scan Logic

### Input
- `apps/dashboard/lib/tabs/generated-registry.ts` — the canonical tab registry
- `apps/dashboard/app/{hub}/` — filesystem for page resolution

### Validation Rules

1. **Hub catch-all check:** Every hub in the registry MUST have `app/{hub}/[[...slug]]/page.tsx`
2. **Tab resolution check:** Every tab href MUST resolve via one of:
   - Direct page: `app/{hub}/{tabId}/page.tsx` exists
   - Catch-all: hub has `[[...slug]]/page.tsx` AND tab's slug path is a key in `[[...slug]]/registry.ts` PAGES map
3. **Registry import check (d2):** Every import path in `registry.ts` PAGES map resolves to an actual file

### Issue Categories

| Category | Severity | Description |
|----------|----------|-------------|
| `missing-catchall` | error | Hub has no `[[...slug]]/` directory |
| `orphan-tab` | error | Tab href resolves to neither direct page nor catch-all entry |
| `dead-registry-import` | warning | Registry.ts PAGES entry imports a nonexistent file |
| `catchall-only-resolution` | info | Tab resolves only via catch-all (valid but fragile) |

## Difficulty Levels

| Level | Scan | Fix |
|-------|------|-----|
| d0 | Check all hubs have catch-all routes | Report only |
| d1 | + validate each tab href resolves | Auto-create missing catch-all dirs (copy template from existing hub) |
| d2 | + cross-check registry.ts imports against actual files | + flag dead imports for removal |

### Auto-Fix (d1+)

For `missing-catchall` issues:
1. Create `app/{hub}/[[...slug]]/` directory
2. Copy `page.tsx` from any existing hub's catch-all (they are identical)
3. Seed `registry.ts` with empty PAGES map and null DEFAULT_PATH
4. Mount-plugins regenerates the registry on next build

No fix for `orphan-tab` — that requires either creating the page or removing the tab from the skill's SKILL.md, which needs human judgment.

## Evolution Gaps

When all checks pass at max difficulty, report:
- Hubs where >50% of tabs resolve only via catch-all (no dedicated page.tsx)
- Any hub with 0 tabs (empty hub)

## Daemon Registration

Add to `skills/daemon/SKILL.md` x-augur-commands:

```yaml
- id: auto-tab-registry
  type: workflow
  visibility: auto
  description: Validate tab registry entries resolve to page files or catch-all routes
  callable: scripts/tab_registry.py
  protocol: scan-fix
  loop:
    name: hardening
    tier: 0
    trigger: nightly
```

## Loop Placement

Hardening loop, tier 0. Runs **before** `auto-code-health` (tsc) and `auto-test-build` (npm build) so tab resolution issues are caught and optionally fixed before the build even starts.

## Implementation Notes

- Parse `generated-registry.ts` as text (regex for hub configs and tab entries) — no Node.js dependency
- The catch-all `page.tsx` is identical across all hubs — copy from any existing one
- `registry.ts` is auto-generated by mount-plugins — seed with empty PAGES map, mount-plugins fills it on next build
- Use `make_issue()` from ops_protocol for all issue creation
- Use `evolution_gap()` when all checks pass at max difficulty
