# ADR-802: Collapse Hubs into Two Fixed Surfaces — Delete the `x-augur-hub` Concept

> **ADR-802 is an index file.** The substantive design and implementation steps live in the linked spec + plan. This file carries pointers, status, and a one-line decision summary.

## Decision summary

Delete the `x-augur-hub` hub abstraction entirely — decomposing its three overloaded jobs (discovery gate, route/tab assignment, Browse grouping) into explicit homes — so the dashboard has exactly two fixed surfaces, **Browse** (`/browse`) and **Workspace** (`/workspace`), with no hub taxonomy or assembly indirection.

## Status notes

**Implemented** (2026-06-07) — all 8 tasks complete. `x-augur-hub` fully removed from skill frontmatter, TS discovery/assembly machinery, generators, Python config, and the Browse filter. Dashboard browser-verified on two surfaces (Browse + Workspace, 11 workspace tabs, no Hub filter); jest 2096 + tsc green. Docs updated; hub-machinery ADRs (ADR-105, ADR-121, ADR-128, ADR-136, ADR-419, ADR-568) marked `superseded_by: ADR-802` in adrs-index.json.

**Accepted** (2026-06-06) — decision ratified. This is the architectural commit governing Phase 2 of the hub collapse; Phase 1 (the user-facing `/brain/*` → `/workspace/*` reframe and the hardcoded Browse + Workspace sidebar) already shipped (commit `6aa508dd4`).

Verification that reshaped the decision: `workspace` is the **only** live dashboard hub (`LIVE_DASHBOARD_HUBS = {"workspace"}`); the `/workspace` route is already generated by a filesystem scan of `features/pages/workspace/`, not by hub assembly; and the backend dev/operation **mode system** that read `x-augur-hub` is **vestigial** (never called in any MCP request path — capability exposure is governed by `config/system/capability_exposure.yaml`). A full deletion therefore carries near-zero backend runtime risk; the only load-bearing job is the dashboard discovery gate, replaced by "a skill is admitted iff it declares `x-augur-dashboard-pages`."

**Supersedes** the hub-machinery ADRs: **ADR-105** (Hub-Driven Plugin Architecture), **ADR-121** (Plugin Hub Ownership & Conflict Validation), **ADR-128** (Contribution-Based Hub Assembly), **ADR-136** (Adaptive Navigation — Nested Skill Promotion), **ADR-419** (Hub Tab Navigation Redesign), **ADR-568** (Track 3b — Dashboard Hub-Routing Redesign). The `superseded_by: ADR-802` bookkeeping on those archived entries is applied in the Phase-2 cleanup step (they are archived; editing requires extract/re-archive). **Ratifies** the already-rewritten CLAUDE.md **rule 13** (two fixed surfaces, no hub taxonomy).
